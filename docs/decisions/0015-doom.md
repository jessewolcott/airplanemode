# 0015. Doom: PrBoom+ in the browser, Freedoom, and an airport episode made in code

Date: 2026-11-22 · Status: accepted

## Context

A real-time game for the hotspot, played on phones. The box's CPU is shared with the model
and the router, and the GL.iNet profile has very little of it, so the game can't run on the
box. Phones have no keyboard. The original Doom's levels and art aren't free to redistribute.

## Decision

- **The game runs in the browser.** `airplanemode-doom` compiles **PrBoom+ 2.6.66** (GPL) to
  WebAssembly with Emscripten (SDL2 port, software renderer, built-in OPL music, ASYNCIFY for
  the main loop). The container is busybox httpd serving static files (32 MB limit); the box
  does no game work. The engine and WAD stages build once on the CI runner, since the output
  is architecture-independent.
- **Touch controls call the engine directly** (`am_key`, `am_mouse`, `am_state` in
  `engine/am_web.c`) instead of faking keyboard events: floating move stick, drag-to-turn,
  Fire/Use/weapon/map/menu buttons, and a menu pad that appears whenever the engine says a
  menu or yes/no question is up. Keyboard, mouse and gamepad work through SDL.
- **Game data that can ship:** **Freedoom** Phase 1 and 2 (BSD), plus **Layover**, a six-map
  airport episode (curbside, security, concourse, baggage underworld, tarmac, control tower)
  made for AirplaneMode. Layover's maps and art are generated by Python in the app repo
  (`wad/`), checked statically (things inside sectors and not stuck, exit reachable with the
  keys you can find), node-built with zdbsp, and use Boom features (moving walkways, carousels,
  UMAPINFO names and a boss trigger). It plays on top of Freedoom: Phase 2.
- **Your own WADs come from Drop.** The page lists `.wad` files in Drop, tells IWADs from mods
  with two range requests, and runs mods on top of a matching IWAD (yours from Drop first,
  else Freedoom). Drop gives `.wad` the type `application/x-doom-wad` and a **Play in Doom**
  button (`opens` in `apps.json`); "downloads off" still lets the Doom app stream the file.
- **Saves and settings stay in the browser** (IndexedDB via Emscripten's IDBFS), per game.

## Consequences

- No multiplayer in 0.1 (PrBoom+ netplay needs UDP; a WebSocket relay would be a later app
  change).
- First start downloads the engine and WADs (about 12 MB gzipped for Freedoom 2 + Layover);
  after that the browser cache serves them.
- iPhone Safari has no fullscreen API for pages: the page is a home-screen web app instead.
- The shareware DOOM1.WAD isn't bundled; people bring commercial WADs themselves via Drop.
- *Untested* on real hardware and real phones (touch was tested with synthetic events in a
  desktop browser).
